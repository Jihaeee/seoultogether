# 위례 아이편한 지도 — 디자인 시스템

**컨셉: 따뜻한 종이 지도 — 아이와 함께 걷는 위례**

유모차를 밀며 한 손으로 보는 화면이다. 공공데이터 대시보드처럼 차갑지 않고,
아이 용품 브랜드처럼 유치하지도 않은 자리 — 크림색 종이 위에 파스텔 스티커를
붙여 둔 동네 지도를 기준으로 삼는다.

세 가지 원칙:

1. **경계선 대신 그림자.** 회색 테두리로 칸을 나누지 않는다. 따뜻한 갈색 계열의
   부드러운 그림자로 층을 만든다.
2. **시설의 색은 끝까지 따라간다.** 필터 칩 → 목록 카드 → 지도 마커 → 팝업까지
   같은 시설은 같은 색을 유지한다. 목록에서 고른 것이 지도의 어느 점인지
   색만으로 이어져야 한다.
3. **둥글게.** 아이콘 PNG의 스퀘어클 실루엣이 형태 언어의 기준이다. 각진
   모서리는 쓰지 않는다.

---

## 파일 구조 — 토큰은 어디에 있나

| 파일 | 역할 |
| --- | --- |
| `src/app/globals.css` | **시스템의 원본.** 토큰(`:root`) + 기본값 + 조각(primitives) + 컴포넌트 |
| `src/lib/tokens.ts` | JS 에서만 필요한 최소 미러 (Leaflet 이 직접 그리는 경로선 색) |
| `src/lib/typeIcons.tsx` | 아이콘 세트 + 크기 스케일 |

새 값이 필요하면 **먼저 `globals.css` 에 토큰을 추가한다.** `tokens.ts` 는
CSS 클래스로 표현할 수 없는 곳에만 쓰는 탈출구이고, 이 목록이 길어진다면
CSS 로 옮길 수 있는 스타일을 JS 에서 그리고 있다는 신호다.

> 이전에는 두 파일이 같은 토큰을 각자 정의하면서 `--paper`, `--bg`, `--line`,
> radius 스케일이 서로 다른 값을 갖고 있었다. 지금은 겹치는 값이 두 개뿐이다.

## 1. 색

### 중립 · 브랜드

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--bg` | `#f7f0e5` | 페이지 바탕. 따뜻한 크림 |
| `--paper` | `#ffffff` | 카드 · 떠 있는 표면 |
| `--bg-sunken` | `#f1e7d8` | 입력창 · 비활성 칩처럼 눌린 면 |
| `--line` | `#ece0cd` | 아주 얕은 구분선. 거의 쓰지 않는다 |
| `--ink` | `#33241b` | 본문 · 제목 |
| `--ink-soft` | `#614d40` | 보조 텍스트 · 라벨 |
| `--muted` | `#6f5b4e` | 3차 정보 · 플레이스홀더 |
| `--accent` | `#c1552f` | **모든 인터랙션** — 버튼, 포커스 링, 경로선, 내 위치 |
| `--accent-strong` | `#a4451f` | accent 의 hover |
| `--accent-soft` | `#fbe2cd` | accent 의 옅은 배경 (도보 아이콘 타일과 같은 색) |
| `--brand` | `#f4829a` | **캠페인 아이덴티티** — 벚꽃 마크의 분홍. 면으로만 쓴다 |
| `--brand-ink` | `#c5375a` | 같은 계열의 글자용. 헤더 에이브로우 |
| `--brand-soft` | `#feeff1` | brand 의 옅은 배경 (브랜드 아이콘 타일과 같은 색) |
| `--naver` | `#03c75a` | **밖으로 나가는 링크** — 네이버 브랜드 초록. 점에만 |
| `--naver-ink` | `#0a7a3d` | 같은 계열의 글자·채움용 (`--naver-soft` 위 4.9:1) |
| `--naver-soft` | `#e6f7ee` | naver 의 옅은 배경 (지도 팝업의 링크 알약) |

**잉크 삼단은 가장 밝은 배경(`--bg-sunken`) 기준으로 잡혀 있다.** 예전 값은
`--muted` 4.57:1 · `--ink-soft` 5.56:1 로 4.5 를 간신히 넘겨 안전 마진이 없었다 —
필터 라벨, 검색 placeholder, 이용 안내가 전부 그 언저리였다. 야외 햇빛 아래
유모차를 밀며 보는 화면에서 실사용 대비는 측정값보다 낮으므로 한 단계씩 내렸다.
지금은 `--muted` 5.23 · `--ink-soft` 6.49 · `--ink` 12.18 이다.

**투명도로 글자를 물리지 않는다.** 정보에 `opacity` 를 얹으면 대비가 그만큼
깎인다. 필터 개수 배지가 `opacity: .65` 로 **2.46:1** 이었고(12px 텍스트),
팝업 제원이 `.8` 로 3.64:1 이었다. 위계는 크기와 굵기로 만든다.

**초록은 "여기를 떠난다"는 뜻으로만 쓴다.** 네이버 지도로 넘기는 링크가 세
자리(목록 카드 · 지도 팝업 · 경로 실패 카드)에 있는데, 전부 클레이색이던 동안
사용자에게는 우리가 하는 일과 다른 앱으로 나가는 일이 같은 색이었다 —
특히 목록 카드에서는 '길찾기'(우리가 경로를 그린다)와 '네이버 지도'(나간다)가
같은 자리를 번갈아 쓴다. 그 자리에서 색이 유일한 구분이다.

브랜드 초록(`#03c75a`)은 흰 바탕에서 2.1:1 이라 13px 볼드 글자로 쓸 수 없다.
시설 아이콘과 같은 방식으로 나눴다 — **면(글자 앞의 7px 점)에만 브랜드 초록을
쓰고, 글자와 hover 채움은 같은 계열을 낮춘 `--naver-ink`** 가 맡는다. 이 자리의
링크에서 `RouteGlyph`(보내기 화살표)를 뺀 것도 같은 이유다. 같은 글리프가
'길찾기'에서는 우리가 그리는 경로를 뜻하고 있었다.

`--accent`(클레이)와 `--brand`(벚꽃)는 역할이 다르다. **브랜드 핑크는 누를 수
있는 것에 절대 쓰지 않는다** — 눌리는 것은 전부 클레이색이라는 규칙이 있어야
사용자가 어디를 누를지 색으로 안다.

`--brand` 를 글자에 쓰면 크림 배경 위에서 2.7:1 밖에 안 나온다. 그래서 글자용
`--brand-ink` 를 따로 둔다.

### 시설 타입

로즈 / 오렌지 / 골드 / 그린 — 네 계열이 서로 확실히 구분되게 잡았다.

| 시설 | `-bg` (타일·칩 배경) | 기본값 (글자) |
| --- | --- | --- |
| 수유실 `nursing` | `#fee3e5` | `#c0324c` |
| 경사로 `ramp` | `#fee5c6` | `#a94e18` |
| 엘리베이터 `elevator` | `#fef0c9` | `#7d6a15` |
| 식당 `restaurant` | `#ebf2d2` | `#5a7538` |

- `-bg` 는 아이콘 타일의 배경색을 픽셀 그대로 가져온 값이다. 칩과 카드 선택
  배경이 아이콘과 정확히 같은 색이 되어 목록이 한 덩어리로 읽힌다.
- 기본값(글자)은 그 타일 위에서 **4.5:1 이상**. 12px 칩이 읽혀야 한다. 아이콘
  그림 색(밝은 파스텔)을 그대로 쓰면 2.8~3.5:1 로 읽히지 않아 어둡게 내렸다.
- 경사로와 엘리베이터는 어두워질수록 같은 갈색으로 수렴한다. 그래서 색상 자체를
  벌려 두었다 — 경사로는 붉은 주황, 엘리베이터는 올리브빛 금색.
- 벡터로 그린 경사로·엘리베이터만 그림 색 토큰을 하나 더 갖는다
  (`--type-ramp-glyph` `#c06b23`, `--type-elevator-glyph` `#a8820a`). 둘 다
  원본 그림 색이 타일 위에서 2.3~2.6:1 밖에 안 나와, 3:1(WCAG 1.4.11 비텍스트
  대비)을 넘도록 낮춘 값이다.

`[data-type="all"]`('전체' 칩)만 `--t-fg` 로 `--accent` 가 아니라
`--accent-strong` 을 쓴다. `--accent` 를 자기 옅은 배경(`--accent-soft`) 위에
올리면 3.66:1 이라 활성 상태의 라벨과 개수가 읽히지 않았다.

**사용법 — 값을 직접 쓰지 않는다.** 마크업에 `data-type` 만 달면
`globals.css` 의 `[data-type="…"]` 규칙이 그 요소에 `--t-fg` / `--t-bg` 를
심어 주고, 안쪽의 `.chip` 이나 텍스트가 알아서 그 색을 따라간다.

```jsx
<article className="place-card" data-type={p.type}>
  <span className="chip">{typeMeta[p.type].label}</span>  {/* 자동으로 시설 색 */}
</article>
```

Leaflet 팝업처럼 문자열 HTML 로 만드는 곳에서도 같은 방식이 통한다 —
`<div class="popup" data-type="nursing">` 하나면 된다.

## 2. 타이포

두 벌만 둔다.

| 역할 | 폰트 | 쓰는 곳 |
| --- | --- | --- |
| `--font-sans` | **Noto Sans KR** (400/500/700/800) | 본문 · UI 전부 |
| `--font-display` | **Jua** (400) | 워드마크, 큰 수치(소요시간·시설 수) |

> 이전에는 Space Grotesk 를 지정했는데 라틴 전용 폰트라 한글은 전부 시스템
> 폰트로 폴백되고 있었다. 한글 폰트는 서브셋이 많아 `next/font` 에서
> `subsets` 를 지정하지 않고 `preload: false` 로 받는다 — `latin` 으로 좁히면
> 한글 글리프가 빠진다.

### 스케일

`--text-2xs` 12 · `--text-xs` 13 · `--text-sm` 14 · `--text-base` 15 ·
`--text-md` 16 · `--text-lg` 18 · `--text-xl` 22 · `--text-2xl` 26 ·
`--text-display` `clamp(22px, 2.6vw, 30px)`

행간: `--leading-tight` 1.3 (제목) · `--leading` 1.55 (기본) ·
`--leading-relaxed` 1.7 (긴 안내문)

### 한글 조판

`body` 에 `word-break: keep-all` 을 건다. 기본값이면 한글이 아무 데서나
줄바꿈돼 "경사/로", "지하82(장지/동)" 처럼 낱말 한가운데가 잘린다.

**글 폭을 `ch` 로 재지 않는다.** `ch` 는 숫자 `0` 의 폭(14px 기준 ~7.8px)이라
한글에는 의미가 없다. 헤더 태그라인의 `max-width: 48ch` 는 373px 로 계산됐는데
한글 47자는 620px 을 쓰므로, 한 줄로 두려고 적은 값이 오히려 두 줄을 만들었다.
한글 1자는 폰트 크기와 거의 같으니 `em` 으로 센다 — 태그라인 `26em`, 이용 안내
본문 `46em`.

**수와 단위는 붙인다.** `<strong>67</strong>개 시설` 처럼 한 요소 안에 두거나
간격을 주지 않는다. flex `gap` 이 사이에 들어가 "67 개 시설" 로 읽히던 자리가
있었다.

## 3. 여백 · 형태 · 층

**여백** — 4px 배수. `--space-1`(4) ~ `--space-10`(64). 임의의 px 값을 쓰지 않는다.

**반경** — `--radius-xs`(6) / `sm`(10) / `md`(14) / `lg`(18) / `xl`(24) /
`2xl`(28) / `full`. 카드는 `2xl`, 떠 있는 작은 UI 는 `lg`, 버튼·칩은 `full`.

**그림자** — 네 단계. 색은 잉크색 계열의 따뜻한 갈색(`rgba(51,36,27,…)`)이지
중립 회색이 아니다.

| 토큰 | 쓰임 |
| --- | --- |
| `--shadow-xs` | 거의 붙어 있는 요소 |
| `--shadow-sm` | 목록 안의 작은 버튼 |
| `--shadow-md` | 카드 · 패널 · 지도 컨트롤 |
| `--shadow-lg` | 지도 위에 뜬 카드(경로 안내) |
| `--ring` | 포커스 링 — `:focus-visible` 전역에 걸려 있다 |

**모션** — `--dur-fast` 120ms(색 전환) · `--dur` 200ms(형태 전환) ·
`--ease` `cubic-bezier(.2,.8,.3,1)`. `prefers-reduced-motion` 에서 전부 꺼진다.

## 4. 조각 (primitives)

`globals.css` 의 §3. 컴포넌트를 새로 만들기 전에 여기부터 본다.

| 클래스 | 설명 |
| --- | --- |
| `.surface` | 카드/패널 바탕 — 흰 배경 + `2xl` 반경 + `md` 그림자 |
| `.surface-float` | 지도 위에 뜨는 것 — `lg` 반경 + `lg` 그림자 |
| `.btn` + `.btn-primary` / `.btn-quiet` | 알약 버튼. 두 종류만 |
| `.btn-icon` | 28px 원형 아이콘 버튼(닫기 ×) |
| `.chip` | 정보 태그. 문맥에 `--t-*` 가 있으면 시설 색, 없으면 중립 |
| `.chip-neutral` | 색을 타지 않는 회색 태그(편의시설 목록 등) |
| `.icon-badge` | 아이콘에 `drop-shadow`. **배경 타일을 덧대지 않는다** — 아이콘 자체가 이미 파스텔 타일이다 |
| `.label` | 작고 자간 넓은 섹션 라벨 |
| `.sr-only` | 스크린리더 전용 텍스트 |

**검색창은 지우기 버튼을 직접 갖는다.** `type="search"` 의 기본 지우기 버튼은
WebKit 에만 있어서, 크롬·파이어폭스에서는 검색어를 되돌리려면 입력창을 눌러 전체
선택하고 지워야 했다. 한 손으로 쓰는 화면에서 그게 가장 번거롭다. 기본 버튼은
`::-webkit-search-cancel-button` 으로 지워 두 개가 되지 않게 한다.

**결과가 0 인 필터 칩은 한 단계 물린다**(`data-empty`). 검색어를 넣었을 때만
생기는 상태다. 누를 수는 있게 남겨 둔다 — 0 이라는 사실 자체가 답인 경우가 있고,
막아 두면 왜 안 눌리는지를 또 설명해야 한다.

### 아이콘

여섯 개(수유실·경사로·엘리베이터·식당·브랜드·도보).

- **벡터** — 경사로, 엘리베이터. 원본 그림의 구성을 그대로 옮기되 획을 굵게
  올렸다. 벡터라야 선 굵기를 우리가 정할 수 있다.
- **원본 그림** — 수유실, 식당, 브랜드, 도보 (`public/icons/*.png`)

`src/lib/typeIcons.tsx` 가 두 종류를 같은 API 로 감싼다.

> **원본 아트를 손으로 다시 그리려 하지 말 것.** 시도해 봤고, 같은 그림이
> 나오지 않는다. 새 아이콘이 필요하면 원본과 같은 손으로 그린 PNG 를 받는
> 쪽이 맞다.

**원본 그림 쪽에는 두 가지 기계적 보정만 했다.** 그림 자체는 원본 그대로이고,
타일의 모양·크기·색도 건드리지 않았다.

1. **확대** — 원본은 글리프가 타일의 52~65%만 채워서, 78%를 채우는 엘리베이터
   옆에 놓으면 혼자 작아 보였다. 채움 비율을 ~76% 로 맞췄다(가로는 80% 제한).
2. **굵히기** — 획을 1~2px(원본 350px 캔버스 기준) 부풀렸다. 수유실·경사로·
   식당은 2px, 도보는 1px, 벚꽃은 0.

> **2px 이 한계다.** 3px 부터 포크 살이 서로 붙고, 아기 머리가 엄마 팔에
> 먹힌다. 래스터 그림의 획을 부풀리는 방식은 빈틈도 같이 줄이기 때문에
> 여기까지가 끝이다. 더 굵게 가야 하는 아이콘은 경사로·엘리베이터처럼
> 벡터로 옮기는 수밖에 없다.

3. **좌우 뒤집기** — 식당 하나만. 원본의 포크(왼쪽)와 숟가락(오른쪽) 자리를
   맞바꿨다. 그림을 다시 그린 것이 아니라 이미지 전체의 거울상이라 획과 색은
   원본 그대로다 — 포크·숟가락·하트가 저마다 좌우 대칭이라 뒤집어도 형태가
   상하지 않는다.

- `public/icons/source/` — 손대지 않은 원본
- `public/icons/` — 앱이 쓰는, 확대·굵히기·(식당은) 뒤집기를 거친 판

**두 종류가 섞여도 한 세트로 보여야 한다.** 그래서 벡터 아이콘도 PNG 와 같은
세로 비율(≈0.84)과 같은 모서리 반경 비율(짧은 변의 24%)로 그린다. 정사각형으로
그리면 필터 칩처럼 나란히 놓이는 자리에서 혼자 튄다.

**크기는 높이 기준이고 너비는 원본 비율로 계산한다.** 원본 타일이 정사각형이
아니라서(브랜드 마크만 가로가 길다), 정사각 박스에 억지로 넣으면 둘 중 하나가
된다.

- width/height 를 같은 값으로 강제 → 그림이 18% 눌린다
- `object-fit: contain` → 눌리지는 않지만 좌우에 빈 띠가 생겨 정렬이 흐트러진다

**크기 스케일** — 픽셀 크기는 `iconSize` 에서만 정한다. CSS 에도 width/height 를
적어 두면 반드시 어긋나므로, CSS 는 배치(그리드 위치·정렬·여백)만 맡는다.

| | 높이 | 쓰는 곳 |
| --- | --- | --- |
| `sm` | 20 | 필터 칩 |
| `md` | 30 | 지도 마커, 안내문 |
| `lg` | 44 | 목록 카드, 팝업, 헤더 브랜드 마크 |
| `xl` | 56 | 경로 안내 카드, 빈 상태 |

**20px 아래로는 타일 아이콘을 쓰지 않는다.** 파스텔 타일이 뭉개져 색 얼룩으로만
보인다. 그보다 작은 자리(길찾기 버튼 등)에는 타일 없이 선으로 그린 `RouteGlyph`
를 쓴다 — `currentColor` 를 따라가므로 버튼의 상태 색을 그대로 물려받는다.

**같은 그림을 두 벌 그리지 않는다.** Leaflet 마커와 팝업은 React 밖에서 HTML
문자열로 만들어지므로, 스펙 하나에서 컴포넌트(`typeIcons`)와 문자열
(`iconMarkup`)을 함께 뽑는다.

## 5. 레이아웃

```
site-header (sticky, 반투명 + blur)
└ 브랜드 락업 + 태그라인(모바일에서 숨김)

shell (max 1280, grid 396px / 1fr)
├ panel   .surface
│  ├ panel-controls — 검색 · 필터        (모바일에서 sticky)
│  ├ sortbar        — 정렬 · 결과 수 · 안내문
│  ├ list           — 장소 카드
│  └ panel-foot     — 요약 (모바일에서는 감춤)
└ map-card .surface — 지도 + 경로 카드

notice — 이용 안내
```

**`sortbar` 는 `panel-controls` 밖에 있다.** 모바일에서 컨트롤 블록을 sticky 로
붙이는데, 정렬과 안내문까지 함께 고정하면 183px 이 아니라 266px — 844px 화면의
31% 를 목록을 훑는 내내 점유한다. sticky 는 조상 컨테이닝 블록 안에서만
살아 있으므로, 일부만 고정하려면 DOM 을 나누는 수밖에 없다. 늘 손에 있어야
하는 것은 검색과 필터이고, 정렬은 한 번 정하면 다시 건드리지 않는다.

**범례는 없다.** 지도 왼쪽 아래를 상시 점유했는데, 바로 옆 패널의 필터 칩이
같은 아이콘 · 같은 라벨을 개수까지 달고 늘 떠 있어 같은 말을 두 번 하고 있었다.
되살리려면 `page.tsx` 의 마크업, `globals.css` 의 `.legend` 블록,
`MapView` 의 `FIT_OPTIONS.paddingBottomRight`(72 → 108)를 함께 되돌린다.

**두 컬럼의 바닥선은 `--canvas-h` 하나로 묶여 있다.**
`clamp(520px, 100vh - 260px, 760px)`. 패널은 이 높이로 못 박고 목록이
남는 공간을 전부 가져간다(`flex: 1; min-height: 0`). 필터가 두 줄로 늘어나도
지도와 어긋나지 않는다.

**모바일(≤850px)** — 한 컬럼, `--canvas-h` 는 420px 고정. 지도가 먼저 오고
(`order: -1`) 목록이 뒤따른다. 위치를 먼저 잡은 뒤 훑게 하려는 순서다.
목록은 자체 스크롤을 버리고 페이지 스크롤에 합류한다 — 스크롤 영역을 중첩하면
터치로 어느 면을 끄는지가 모호해진다.

그 대가로 두 가지를 함께 둬야 한다.

1. **`panel-controls` 를 `--header-h`(68px) 아래에 sticky 로 붙인다.** 그렇지
   않으면 검색·필터가 카드 67장과 함께 위로 사라져, 필터를 바꾸려면 끝까지
   되올라와야 한다. `.panel` 의 `overflow: hidden` 을 `visible` 로 열어야
   sticky 가 산다 — 조상이 스크롤 컨테이너가 되면 스크롤하지 않는 그 안에서
   sticky 는 아무 데도 붙지 않는다.
2. **결과 수를 `sortbar` 로 올린다.** 바닥 요약줄(`panel-foot`)은 카드 67장
   아래로 밀려나므로 모바일에서는 감춘다. 스크롤 중에 필요한 "지금 필터의 결과
   수"는 sticky 로 남는 필터 칩의 개수 배지가 이미 들고 있다.

**터치 타겟은 44px 이 하한이다.** 유모차를 밀며 한 손으로 보는 화면이라고
적어 두고 실제 높이는 정렬 알약 24px, 길찾기 26px, 닫기 28px 이었다.
WCAG 2.5.8(24px)은 겨우 넘지만 흔들리는 유모차와 겨울 장갑을 전제하면
iOS HIG · Material 권장(44px)이 기준이어야 한다. 필터 칩 · 정렬 알약 ·
길찾기 · 닫기 · 줌 · 내 위치를 850px 이하에서 44px 로 올린다.

## 5.3 장소 카드 — 제목 줄의 예산

카드 제목은 한 줄이고 넘치면 잘린다(`text-overflow: ellipsis`). 그래서 **그 줄에
무엇을 올릴지가 곧 시설명이 몇 자까지 보이는지**를 정한다.

한때 제목 줄에 [시설명][타입 칩][거리]가 함께 있었고, 396px 패널에서 시설명에
남는 폭은 약 146px(9자)이었다. 그런데 같은 역에 엘리베이터가 둘씩 있어 이름
끝에 승강장을 붙여 둔 상태였다(`거여역 엘리베이터 · 개롱 방면 6-2`, 21자).
**잘려 나가는 부분이 정확히 그 구분어라, 목록에는 `거여역 엘리베이터…` 두 장이
그대로 남았다.** 데이터에서 이름을 정정해 두고도 화면에서는 중복이 되돌아온 것이다.

지금은 두 가지로 예산을 만든다.

1. **구분어를 제목에서 뗀다.** `splitName()` 이 첫 ` · ` 를 기준으로 나누고,
   아래 줄 `.place-where` 가 받는다. 표시값은 `whereOf()` — `location` 을 먼저
   쓴다(이름의 구분어보다 늘 같거나 더 자세하다: `2번 출구` vs `2번 출구 측`).
2. **타입 칩을 제목 줄에서 뺀다.** 84px 를 먹는데, 왼쪽 아이콘이 이미 같은 색 ·
   같은 모양으로 종류를 말하고 있었다. 팝업에는 그대로 둔다 — 거기는 폭이 288px 로
   넉넉하고, 카드와 달리 맥락 없이 단독으로 열린다.

결과: 시설명이 쓸 수 있는 폭 230px(14자). 브라우저에서 확인한 값으로 **67장 중
제목이 잘리는 카드는 0장**이고, 제목+부제 조합이 겹치는 카드도 0장이다.

**본문은 라벨 열을 두지 않는다.** 주소 앞의 `주소` 라벨은 값을 40px 들여쓰기해,
0 에서 시작하는 제목·부제·요약과 왼쪽 정렬선을 어긋나게 했다. 라벨 열이 값어치를
하려면 최소 두 행이 있어야 하는데 위치 행이 부제로 올라간 뒤로는 한 행뿐이다.
메뉴처럼 라벨이 꼭 필요한 줄은 열이 아니라 문장 앞에 굵게 붙인다(`.place-menu`).

**카드에 보이는 태그는 두 개다**(`MAX_CARD_CHIPS`). 세 개이던 값은 길찾기 버튼과
한 줄에 앉지 못했다 — `.place-foot` 285px 에 칩 셋(207) + 버튼(82) + 간격(8)이
297px 라 12px 넘쳤고, 목록 앞 여덟 장 중 넷이 두 줄로 접혔다. 지금 카드 높이
편차는 종류별로 20~24px 이다(전체 62px, 나머지는 좌표 없는 다섯 장이 메뉴를 더
싣기 때문).

`note` 는 원래 마커 팝업에만 있었다. 좌표가 없는 5곳은 마커가 없어 팝업으로 갈
길 자체가 없으므로, **그 카드에서만** `note` 와 메뉴를 카드에 편다. 나머지 62곳은
카드를 누르면 팝업이 열리므로 카드를 무겁게 하지 않는다.

## 5.4 지도는 페이지 스크롤을 가로채지 않는다

모바일에서 지도는 목록 위(`order: -1`)에 420px 로 앉아 있다. Leaflet 기본값
(`dragging: true`)이면 **화면을 처음 쓸어내릴 때 페이지가 아니라 지도가 끌린다** —
목록에 닿으려면 지도를 피해서 스와이프해야 한다는 걸 사용자가 알아내야 했다.
유모차를 밀며 한 손으로 보는 화면에서 가장 비싼 실수다.

그래서 손가락 입력(`pointer: coarse`)일 때는 끌기를 잠근 채 시작하고, 지도를 한 번
탭하면 푼다. 잠긴 동안 오른쪽 위에 `지도를 눌러 움직이기` 힌트를 띄운다 — 말해
주지 않으면 안 움직이는 것을 고장으로 읽는다.

이게 되는 이유는 Leaflet 의 CSS 에 있다. `touch-action` 을 조이는 것은 Drag
핸들러가 켜질 때 붙는 `.leaflet-touch-drag`(→ `pinch-zoom`)이고, 잠긴 동안에는
`.leaflet-touch-zoom` 의 `pan-x pan-y` 만 남는다. 세로 스와이프가 페이지
스크롤로 그대로 흘러가고 **두 손가락 확대는 잠긴 동안에도 된다.**
휠 줌(`scrollWheelZoom`)은 입력 방식과 무관하게 끈다 — 데스크톱에서 페이지를
스크롤하다 지도 위를 지나면 확대되던 문제가 같은 뿌리다.

**한 곳을 열 때 배율에 상한을 둔다**(`SELECT_MAX_ZOOM` 17). 클러스터의
`zoomToShowLayer` 는 최대 배율(19)까지 파고들어, 건물 번지만 보이는 화면에서
그게 위례 어디쯤인지 알 수 없게 만들었다. `FIT_OPTIONS.maxZoom` 을 둔 것과 같은
이유이고, 이 경로에는 그 제한이 걸리지 않았다.

**모바일에서는 팝업 높이를 묶는다.** 420px 짜리 지도에서 식당 팝업이 323×376,
지도 면적의 79% 를 덮었다 — 지도 위에 뜬 카드인데 지도가 안 보인다. 식당이
48/67 이라 흔한 경우가 그랬다. `.leaflet-popup-content` 를 232px 로 묶고 안에서
스크롤하게 해 56% 로 내렸다.

> 더 옳은 답은 **모바일 상세를 팝업이 아니라 목록 쪽 바텀시트로 옮기는 것**이다.
> 420px 지도는 288px 팝업의 그릇이 아니다. 로드맵에 남긴다.

**배경 지도는 OpenFreeMap 이다(키 없음).** 원래는 CARTO Voyager 였는데, CARTO 가
키 없는 사용을 끊고 **모든 타일에 `API KEY REQUIRED` 를 찍어서** 내려보내기
시작했다. 타일은 200 으로 정상적으로 오고 그림에만 글자가 박히므로, 코드에서는
아무 오류도 나지 않는다 — 화면을 열어 봐야 알 수 있는 고장이었다.

키도 계정도 없이 쓰는 것이 조건이었다. 이 지도는 누가 언제 다시 배포할지 모르는
캠페인 시안이라, 키를 넣는 순간 그 키를 관리하는 사람이 계속 필요해진다. OSM
표준 타일은 진한 도로색과 빨간 경계 점선이 파스텔 마커를 덮어 §1 의 색 규칙이
지도에서만 깨진다. 남은 것이 OpenFreeMap positron — 연한 회백 벡터 지도이고,
키도 요청 수 제한도 없다.

벡터라 렌더링은 WebGL 로 간다. **Leaflet 은 그대로 두고 배경 레이어만
`maplibre-gl-leaflet` 으로 바꿔 끼웠다** — 마커·클러스터·팝업·경로선은 전부
예전 그대로다. 두 가지가 딸려 왔다.

- **배율 상한이 지도 자신의 옵션으로 옮겨 왔다**(`MAX_ZOOM`). 예전에는 타일
  레이어가 들고 있었는데 그 레이어가 없어졌다. markercluster 는 지도의 maxZoom
  이 유한하지 않으면 붙는 순간 예외를 던지므로, 이건 없으면 안 되는 값이다.
- **라벨을 한국어로 다시 세운다.** 기본 스타일은 `Wirye-daero 위례대로` 처럼
  라틴 이름과 현지 이름을 붙여 두 번 적는다. 좁은 화면에서 라벨끼리 더 자주
  부딪히고, 읽는 사람은 한 번도 읽지 않는 절반을 계속 지나쳐야 한다.
- WebGL 이 열리지 않는 기기에서는 OSM 래스터로 물러선다. 배경이 못생긴 것보다
  지도가 아예 없는 것이 훨씬 나쁘다.
- **벡터 타일은 워커 안에서 받아 파싱된다.** 번들러를 지나면 MapLibre 가 계산한
  워커 주소가 문서 주소로 떨어져, 타일 요청이 한 번도 나가지 않고 **배경색만
  칠해진 빈 지도**가 됐다. 콘솔에는 한 줄만 남고 예외는 나지 않는다. 워커 파일을
  `public/maplibre/` 로 복사해 두고 주소를 못 박는다(`npm run sync:maplibre`,
  predev/prebuild 에 걸려 있다).

**배경 지도의 색도 우리가 정한다.** 벡터로 옮긴 값이 여기서 나온다 — 래스터
타일이었다면 제공사가 칠해 준 색을 그대로 받는 수밖에 없다. positron 의 중성
회색(rgb 242,243,240) 위에서는 파스텔 마커가 **남의 지도에 붙인 스티커**처럼
보였다. 지도는 페이지 위에 얹힌 창이 아니라 같은 종이의 일부여야 한다.

색은 `mapColor`(tokens.ts)에 모여 있다. CSS 가 한 번도 읽지 않는 값이라
`globals.css` 에 토큰을 만들지 않았다 — 땅·물·건물·도로는 MapLibre 가 캔버스에
직접 칠한다. 읽는 방식은 두 가지로 못 박았다.

- **포장된 것은 땅보다 밝다** — 큰 길은 종이 흰색이고, 크림색 바닥에서 사라지지
  않도록 테두리(casing)를 남긴다.
- **선 것은 땅보다 어둡다** — 건물. 도로망과 건물 덩어리가 밝기의 반대 방향으로
  갈리므로 배율을 낮춰도 형태가 읽힌다.

**작은 길만은 예외로 땅보다 어둡다.** 처음에는 큰 길처럼 밝혔는데 테두리가 없는
선이라 크림색 위에서 거의 사라졌다. 흰 길은 테두리가 받쳐 줄 때만 길로 읽힌다 —
원래 스타일이 작은 길만 어둡게 긋는 이유도 같다.

물빛만 팔레트 밖에서 가져왔다(먼지 낀 파랑). 따뜻한 색으로 칠한 물은 물로
읽히지 않는다. 대신 채도를 최대한 빼서 크림 옆에 놓이게 했고, 물 이름도 잉크가
아니라 그 물빛 계열을 쓴다.

**장소 이름은 우리가 얹는다.** positron 은 데이터 위에 깔기 위한 바탕이라 이름을
붙이는 층이 물길·도로·행정 지명뿐이다 — 가게도 건물도 이름이 없다. 옮기고 나니
"가든파이브가 어디지"에 지도가 답을 못 했다. 마커는 우리 시설만 찍혀 있어서, 그
사이의 빈 땅이 무엇인지 말해 주는 것이 하나도 없었다.

스타일을 통째로 바꾸지(bright/liberty) 않고 `poi` 층만 얹은 이유는 **이름만
필요하기 때문**이다. 그 스타일들로 가면 도로색과 건물색이 함께 진해져 파스텔
마커가 배경에 묻힌다 — §1 의 색 규칙이 지도에서만 깨진다. 얹을 때 셋을 눌러 둔다.

- **글자만.** 배경의 상점 아이콘이 섞이면 무엇이 조사된 시설인지 흐려진다.
- **z15 부터.** 첫 화면이 z15 다. 그 아래에서는 이름이 아니라 동네가 보여야 한다.
- **rank 20 까지.** 전부 켜면 한 건물에 들어찬 가게 이름이 마커를 덮는다.

**겹친 곳은 지도 위에 펼치지 않고 목록으로 고른다.** 지오코딩한 좌표가 건물
단위라 가든파이브 9곳·파크하비오 7곳이 한 점에 포개진다. 처음에는 markercluster
의 spiderfy 를 그대로 썼다 — 배지를 누르면 마커가 다리(선)를 달고 방사형·나선형
으로 뻗어 나가는 그 동작이다. 두 가지가 걸렸다.

- **지도 위에서 튄다.** 손으로 그린 파스텔 타일과 둥근 카드로 짜인 화면에,
  기하학적으로 뻗는 선다발은 다른 언어다.
- **답을 주지 않는다.** 펼침이 답한 질문은 '몇 개인가'뿐이다. 어느 것이
  무엇인지는 결국 아이콘을 하나씩 눌러 봐야 했다.

그래서 배지 클릭을 두 갈래로 갈랐다. **확대하면 갈라지는 묶음이면 그 범위로
확대하고**(라이브러리 기본과 같다), **어떤 배율에서도 갈라지지 않는 묶음이면
겹친 곳들의 이름을 목록 카드로 띄운다.** 판정은 markercluster 자신이 쓰는 것과
같은 것을 그대로 가져왔다(`splitsOnZoom`). 목록의 한 줄을 누르면 카드 클릭과
같은 길로 흘러가고, 그 곳의 팝업이 같은 자리에 다시 열린다.

목록에서 고른 곳을 여는 일에는 `zoomToShowLayer` 를 쓰지 않는다. 그 함수는
확대해도 마커가 드러나지 않으면 마지막에 `spiderfy()` 를 부르기 때문이다 —
가든파이브처럼 '갈라지는 묶음 안의 겹친 아홉 곳'은 정확히 그 경로로 들어간다.
같은 일을 세 갈래로 나눠 직접 한다(`revealPlace`): 홀로 서 있으면 그대로 열고,
갈라지는 묶음이면 확대한 뒤 다시 보고, 끝내 갈라지지 않으면 그 좌표 위에 팝업만
연다. 배지는 숫자인 채로 두고 어느 곳인지는 팝업의 이름이 말한다.

**길찾기가 열려 있는 동안에만 위치를 따라간다.** `watchPosition` 은 켜 두면
배터리를 계속 먹는다 — 유모차를 밀며 여는 화면에서 배터리는 부가 정보가 아니라
기능이다. 그래서 사용자가 실제로 걷고 있다고 말할 수 있는 유일한 구간, 경로
카드가 떠 있는 동안에만 켜고 닫으면 끈다.

**따라 움직이는 것은 지도의 점뿐이다.** 좌표를 둘로 나눠 둔다(`useUserLocation`).

- `coords` — 목록 정렬과 카드의 거리가 쓰는 **기준점**. 버튼으로 잴 때만 바뀐다.
- `liveCoords` — 지도에 찍는 **지금 위치**. 추적 중에는 이쪽만 갱신된다.

걷는 동안 목록까지 따라 움직이면 거리순이 계속 뒤집혀, 누르려던 카드가 손가락
밑에서 사라진다. 대신 추적을 끄는 순간(길찾기를 닫을 때) 마지막 좌표를 기준점
으로 올린다 — 순서가 바뀌는 것은 그 한 번뿐이고, 그때는 사용자가 이미 카드를
누르는 중이 아니다.

**지도는 따라가되, 매번 가운데로 끌어오지 않는다.** 5m 마다 화면이 들썩이면
지도를 읽을 수 없다. 점이 화면 가운데 절반 밖으로 나갔을 때만 그 자리로
옮기므로(`panTo`), 걷는 동안 지도는 몇 걸음에 한 번씩만 움직인다. 경로를
그리면서 맞춘 첫 화면(출발지~목적지 전체)은 그대로 두고, 걷기 시작한 뒤의
갱신부터 따라간다.

**사용자가 지도를 끌면 따라가기가 풀린다.** 지금 보려고 옮긴 자리를 다음 좌표가
도로 뺏어 가면, 걷는 동안 지도를 들여다볼 방법이 없어진다. 다시 켜는 길은
'내 위치로 이동' 버튼이다 — 그 버튼은 "내 위치를 보여 달라"는 말이므로 따라가기
재개와 같은 뜻이다. 확대·축소 버튼은 풀지 않는다(따라가면서 확대할 수 있다).

**보고 있는 방향은 부채꼴로 얹는다**(`useHeading`). 점이 "여기 있다"까지만
말하면, 길을 나설 때 남는 물음이 하나 있다 — 어느 쪽으로 서 있는가. 유모차를
돌려 세워 가며 지도와 눈앞을 맞춰 보는 그 몇 초를 없애는 것이 이 부채꼴이
하는 일이다.

방향은 위치와 **다른 센서**(자력계)이고, 되는 조건도 따로 논다. 그래서 **없을
수 있는 정보**로 다룬다 — 없으면 부채꼴을 그리지 않고, 없다고 안내하지도
않는다. 방향은 있으면 편한 것이지 없으면 못 걷는 것이 아니다.

- **iOS 13+ 는 따로 허락을 받는다.** `requestPermission()` 은 사용자 제스처
  안에서만 통하므로, 훅이 스스로 묻지 않고 길찾기 확인 버튼과 '내 위치'
  버튼이 부른다. 거절해도 위치와 경로는 그대로 된다.
- **HTTPS 가 아니면 이벤트가 오지 않는다.** `localhost` 는 예외지만, 폰에서
  `http://192.168.…` 로 열어 본 화면에는 방향만 조용히 없다.
- **자력계가 없으면**(데스크톱 대부분) GPS 의 진행 방향으로 물러선다. 그건
  걷고 있을 때만 나오므로, 서면 부채꼴이 사라진다.

각도는 이어 붙여 내보낸다(370°, -20° 같은 값). 0~360 을 그대로 CSS 회전에
넣으면 359°→1° 에서 화살표가 한 바퀴를 거꾸로 돈다. 1~2° 짜리 떨림(3° 미만)은
버리고, 각도가 바뀔 때 마커를 다시 만들지 않고 부채꼴의 `transform` 만 고쳐
쓴다 — 다시 만들면 맥박 애니메이션이 매번 처음으로 되돌아간다. 방향이 켜지는
동안에는 그 맥박을 멈춘다. 둘이 함께 움직이면 작은 화면에서 얼룩으로 보인다.

제자리 흔들림(5m 미만)은 버린다. 다만 오차 반경이 눈에 띄게 좁아진 갱신은
받는다 — 같은 자리라도 "200m 안 어딘가"가 "10m 안"이 된 것은 정보다. 그린
경로선과 소요시간은 걷는 동안 다시 계산하지 않는다. 매 걸음마다 라우터를
부르는 셈이 되고, 화면의 숫자가 계속 바뀌면 읽을 수 없다.

**마커 클릭은 목록 선택으로 이어진다.** 예전에는 목록 → 지도 한 방향뿐이라,
묶인 아홉 곳을 펼쳐 하나를 고른 뒤 "이게 목록의 어느 가게지"에 답이 없었다.
§1 의 색으로 잇겠다는 규칙이 한쪽으로만 지켜지고 있었던 셈이다.

두 가지를 함께 둬야 서로 부딪히지 않는다.

- 마커에서 온 선택이면 `zoomToShowLayer` 를 건너뛴다. 사용자가 이미 보고 누른
  마커를 다시 화면 밖으로 밀어낼 이유가 없다(`fromMarkerRef`).
- 카드에서 온 선택이면 지도를 스크롤로 데려온다(`selectFromList`). 모바일에서
  지도가 목록 위에 있어, 한참 내려온 뒤 카드를 누르면 팝업이 화면 밖에서 열린다.

**팝업도 마커 핸들러에서 직접 연다.** 클러스터 그룹에 묶인 마커는 `bindPopup` 이
심어 두는 Leaflet 기본 열기가 걸리지 않는다 — 브라우저에서 확인했다. 카드 클릭은
열리는데(그 경로는 `openPopup()` 을 명시 호출한다) 마커 클릭은 팝업이 아예 뜨지
않았다. `isPopupOpen()` 으로 막아 두는 이유는, 기본 열기가 걸리는 경우 그쪽이
토글이라 무조건 열면 마커를 눌러 닫을 수 없게 되기 때문이다.

## 5.5 이 지도는 누구의 것인가

**1차 대상은 영유아를 동반한 보호자 하나다.**

경사로·엘리베이터 데이터의 출처는 휠체어 접근성 공공데이터이고, 그래서 원문에는
"휠체어 경사로", "정격하중 1,000kg" 같은 표현이 섞여 있다. 이 값들을 그대로
노출하면 대상이 둘인 것처럼 보이지만, 실제로는 **어느 쪽에도 맞지 않는 화면**이
된다 — 유모차를 미는 사람에게 정격하중은 아무 뜻이 없고, 휠체어 이용자에게
"아이와 함께"라는 카피는 자기 이야기가 아니다.

그래서 한쪽으로 좁혔다.

- 데이터는 유모차 관점으로 **번역해서** 싣는다. 제원(정원·정격하중)은 버리지
  않되 팝업 맨 아래로 내리고(`spec`), 앞자리에는 부모가 실제로 묻는 것을 둔다 —
  개찰구 안인가 밖인가(`gate`), 이 엘리베이터 하나로 지상까지 가는가(`note`).
- 휠체어 이용자를 1차 대상으로 삼는 판(헤더 카피·아이콘·태그라인 전면 개편)은
  로드맵에 남긴다. 데이터 활용도는 높지만 캠페인 기간에 할 수 있는 크기가 아니다.

`gate` 값은 조사 원문의 `내부`/`외부`와 승강장 위치 표기에서 옮긴 것이고,
근거가 없으면 비워 둔다 — 비면 `개찰구 확인 필요` 태그가 붙는다. 없는 것과
모르는 것을 같은 칸에 두지 않는다는 §6 의 원칙이 여기에도 그대로 적용된다.

## 6. 데이터가 불완전할 때

식당 조사자료 48곳 중 **5곳은 아직 주소만 있고 좌표가 없다.** 목록에는 67곳이
보이는데 지도에는 62곳만 찍힌다는 뜻이다. 이 차이를 숨기지 않는다.

> 이 수치는 지오코딩 전에 41곳이 좌표가 없던 시절의 값(68곳 · 지도 27곳)에서
> 바뀐 것이다. **데이터를 채웠으면 이 문단도 함께 고칠 것** — 실제와 다른 숫자가
> 적힌 설계 문서는 다음 사람에게 틀린 근거가 된다.

- 요약줄에 그대로 적는다 — `67개 시설 · 지도 표시 62곳`
- 좌표가 없으면 마커를 만들지 않는다. `markersRef` 에 아예 들어오지 않으므로
  표시·선택·경로 로직이 자연히 이들을 건너뛴다.
- 카드의 액션이 바뀐다. 좌표가 있으면 **길찾기**(도보 경로), 없으면
  **네이버 지도**(외부 링크). 둘은 하는 일이 다르지만 카드에서 차지하는
  자리는 같다.

### `note` 는 두 가지 일을 겸하고 있다

역 시설 19건의 `note` 는 판단에 곧바로 쓰이는 안내다 — "표를 찍지 않고 들를 수
있습니다", "지상으로 나가려면 개찰구 밖 엘리베이터를 한 번 더 타야 해요".

**식당 48건은 전부 같은 한 줄이고, 그 내용이 조사자료 이름이다**("영유아 친화
식당 조사자료"). 팝업 48장에 구분선까지 두고 같은 문구를 띄우면 그건 정보가
아니라 배경 소음이 되고, 정작 읽어야 할 줄을 밀어낸다 — "기저귀 확인 필요" 칩을
48곳에 달지 않은 것과 같은 판단이다. 출처는 페이지 아래 이용 안내가 한 번 말한다.

그래서 화면은 `note` 를 그대로 쓰지 않고 `guidanceFor()` 를 지난 값을 쓴다.
걸러 내는 기준을 **문장**으로 둔 이유는, 나중에 식당별 실제 안내가 조사되면
코드를 고치지 않고 그대로 뜨게 하려는 것이다. 타입으로 끊으면 그때 다시 손대야 한다.

### 그 밖의 빈칸 원칙

조사 원문의 애매함도 뭉개지 않는다. 유모차 출입은 `O`/`○`(가능)와 `△`(조건부)가
섞여 있는데, 조건부를 '가능'으로 합치면 2층 매장에 유모차를 끌고 갔다가
헛걸음하게 된다. 그래서 태그를 **유모차 반입** / **유모차 확인 필요** 로 나눈다.
판정은 `chipsFor` 한 곳에서만 한다.

## 7. 접근성

- `:focus-visible` 에 전역 포커스 링. 마우스 클릭에는 나타나지 않는다.
- **쓸 수 없는 컨트롤에 `disabled` 를 쓰지 않는다.** 위치 권한이 꺼졌을 때
  '가까운 순'은 `aria-disabled` 다. 진짜로 끄면 포커스가 가지 않아, 바로 아래
  붙여 둔 이유(`aria-describedby="sort-note"`)를 스크린리더가 읽어 줄 자리가
  사라진다. 눌리기는 하되 아무 일도 하지 않고, 상태는 취소선으로 — 색만으로
  전하지 않는다는 아래 규칙을 여기서도 지킨다.
- 경로 UI 는 세 상태 전부 `role="status"` 다. 예전에는 로딩·실패에만 있어서
  스크린리더 사용자는 "경로 찾는 중…" 다음이 조용했다. 목록 결과 수
  (`.panel-foot` · `.result-count`)도 `aria-live="polite"` 로 필터 변경을 알린다.
- 필터와 장소 카드는 `aria-pressed` 로 선택 상태를 알린다. **선택 상태를 색으로만
  전하지 않는다** — 상태는 속성에 있고, CSS 가 그 속성을 보고 칠한다
  (`.filter[aria-pressed="true"]`).
- 장소 카드는 `role="button"` + `tabIndex={0}` + Enter/Space 처리. 안쪽에 길찾기
  버튼이 있어 `<button>` 으로 감쌀 수 없다(중첩 불가).
- 장식용 아이콘은 전부 `alt=""` + `aria-hidden`.
- 경로 상태 표시는 `role="status"`.
- `prefers-reduced-motion` 에서 애니메이션 정지.
